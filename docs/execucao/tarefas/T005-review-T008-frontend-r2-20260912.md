# Revisão independente T008 r2 — alertas pendentes

O helper `mobile/src/utils/alertState.ts:4-18` corrige o defeito anterior: lista vazia retém somente IDs com `alert_create`/`alert_update`; sem outbox retorna `serverAlerts` vazio e uma linha do servidor substitui a local. Os testes `mobile/tests/alert-state.test.cjs` cobrem os dois cenários e precedência do servidor. Execução: `node --test tests/alert-state.test.cjs tests/checkpoint-pending.test.cjs` (6/6); `npx tsc --noEmit` passou.

**Ainda devolvo por isolamento de usuário.** `mobile/src/db/database.ts:144-153` grava outbox sem `user_id`; `mobile/src/db/repositories.ts:77-86,88-92` cria alerta local com `user_id: 0`; `AuthProvider.tsx:144-149` no logout apenas fecha sessão/remove token, sem limpar ou separar outbox/alertas. O helper compara apenas `entity_key`/ID. Portanto, após logout de A e login offline de B, uma operação pendente de A pode ser preservada e enviada com o token de B, ou uma linha local de A pode aparecer para B. A correção precisa escopar cada operação/linha ao usuário autenticado ou descartar/segregar pendências na troca de usuário, mantendo a ordem da fila. Não há aceite de código enquanto esse caso não tiver teste.
