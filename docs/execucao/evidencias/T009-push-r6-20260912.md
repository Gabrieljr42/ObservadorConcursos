# T009 push r6 — nulabilidade PostgreSQL do soft revoke

Correção limitada ao P1 de integração: `push_devices.token_fingerprint` não
pode ser `NOT NULL`, pois o revoke persistente limpa `token` e
`token_fingerprint`. O schema novo agora declara ambos nullable; o upgrade
idempotente PostgreSQL executa `ALTER COLUMN ... DROP NOT NULL` para `token` e
`token_fingerprint` antes de recriar/garantir o índice único. Índices únicos
PostgreSQL preservam múltiplos valores nulos.
